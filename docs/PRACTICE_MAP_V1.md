# Practice Map v1

This document is the **library map**, not a linear curriculum.

It answers:

> Which real-life conversations should an Englotti learner be able to choose from at each level?

A mission appearing here is a design commitment to a real communicative problem. It is **not yet a published mission** until its full contract, sources, runtime behaviour, Listening Preview where required, and Live QA pass review.

## Status

- A1: **first full map drafted below**
- A2: next mapping pass
- B1: next mapping pass after A2, while preserving the existing B1 vertical-slice experiments as research
- B2–C2: map after lower-level progression is visible

There is no mandatory order inside a level.

`Core` means **Great place to start**, not prerequisite.

# A1 design boundary

A1 Practice should feel safe, concrete, and predictable:

- one clear real-world goal
- roughly 3–6 meaningful learner moves
- short partner turns
- collaborative interlocutor
- familiar information
- tight or mostly linear graph
- no hidden complication required for success
- short formulaic language is valid where natural
- dynamic hints available on demand

A1 should not require extended explanation, negotiation, storytelling, or subtle register management.

# A1 Core / Great place to start

These missions give a beginner a broad first taste of Practice without creating a required sequence:

1. `A1-PS-01` — Meet someone new
2. `A1-EV-01` — Ask someone to repeat
3. `A1-FS-01` — Order a drink
4. `A1-FS-03` — Buy one item and ask the price
5. `A1-TT-01` — Ask where a place is
6. `A1-TT-03` — Check into a hotel
7. `A1-HS-02` — Book a simple appointment
8. `A1-PL-03` — Make a simple plan

All A1 Core missions require an authored Listening Preview before full publication. The preview remains optional for the learner.

# A1 mission library

## Everyday Life — 4 missions

### A1-EV-01 — Ask someone to repeat ★ Core

**Goal:** recover when one simple thing was not understood, hear it again, and confirm the detail.

**Communication problem:** `clarify / repair`

**Likely shape:** hear detail -> ask to repeat / slow down -> hear again -> confirm -> close.

**Why A1:** one predictable repair move with a cooperative partner.

**Listening Preview:** required before full publication.

---

### A1-EV-02 — Exchange contact details

**Goal:** exchange one or two simple contact details and repair spelling/repetition if needed.

**Communication problem:** `ask information + give information + spelling repair`

**Likely shape:** ask name/contact -> give chosen or fictional detail -> spell/repeat -> confirm.

**Privacy rule:** no hardcoded real learner phone, email, address, or identity. Product examples use fictional data or placeholders.

**Listening Preview:** recommended.

---

### A1-EV-03 — Check what time something starts

**Goal:** ask what time a familiar event/service starts and confirm the time.

**Communication problem:** `ask information + confirm`

**Likely shape:** ask start time -> hear time -> confirm / thank -> close.

**Listening Preview:** optional/recommended when the time language is central.

---

### A1-EV-04 — Ask for simple help

**Goal:** get basic practical help with one clear, visible need.

**Communication problem:** `request help`

**Likely shape:** get attention -> ask for help -> state/point to simple need -> partner helps -> thank.

**Authoring note:** the need must remain concrete enough for A1; do not turn this into explaining a complex problem.

**Listening Preview:** recommended.

## People & Social — 3 missions

### A1-PS-01 — Meet someone new ★ Core

**Goal:** greet someone, exchange names, handle one simple social question, and close naturally.

**Communication problem:** `social opening + information exchange + closing`

**Likely shape:** greeting -> name -> simple wellbeing/basic question -> reciprocal move -> close.

**Listening Preview:** required before full publication.

---

### A1-PS-02 — Talk about where you're from and where you live

**Goal:** ask and answer simple origin/residence questions without confusing the two meanings.

**Communication problem:** `ask information + give information`

**Likely shape:** ask where from -> answer -> ask where live -> answer -> react simply.

**Privacy rule:** learner may use real, chosen, fictional, or placeholder information. The mission must not require disclosure of personal information to succeed.

**Listening Preview:** recommended.

---

### A1-PS-03 — Introduce another person

**Goal:** introduce another person with a name and one simple fact, react politely, and close the introduction.

**Communication problem:** `introduce + give simple information + social reaction`

**Likely shape:** introduce person -> give one fact/relationship -> partner reacts -> learner responds -> close.

**Listening Preview:** recommended.

## Food & Shopping — 4 missions

### A1-FS-01 — Order a drink ★ Core

**Goal:** order one available drink, answer one predictable service question, handle the price/payment exchange, and close.

**Communication problem:** `request + transaction`

**Likely shape:** order -> choose size -> hear price -> complete exchange -> close.

**Status:** first authored vertical-slice mission exists as `practice.a1.food.order-drink.v1`.

**Listening Preview:** required before full publication.

---

### A1-FS-02 — Order a simple meal

**Goal:** order one simple food item and answer one predictable follow-up such as here/takeaway or one basic choice.

**Communication problem:** `request + respond + transaction`

**Likely shape:** order -> answer one service choice -> confirm -> close.

**Authoring note:** keep menu truth very small. Do not turn this into preferences, substitutions, allergies, or complaint handling; those belong above A1.

**Listening Preview:** recommended.

---

### A1-FS-03 — Buy one item and ask the price ★ Core

**Goal:** ask for one familiar item, ask/understand the price, decide to buy it, and close.

**Communication problem:** `request + ask information + transaction`

**Likely shape:** ask for item -> ask price -> hear price -> accept/buy -> close.

**Listening Preview:** required before full publication.

---

### A1-FS-04 — Ask for a size or colour and choose

**Goal:** ask whether a familiar product is available in one size/colour and make a simple choice.

**Communication problem:** `availability question + choice`

**Likely shape:** ask for item/variant -> hear available options -> choose -> close or buy.

**Authoring note:** no negotiation or complicated comparison at A1.

**Listening Preview:** recommended.

## Travel & Transport — 4 missions

### A1-TT-01 — Ask where a place is ★ Core

**Goal:** ask where one nearby familiar place is and understand a very simple direction/location answer.

**Communication problem:** `ask information + simple location understanding`

**Likely shape:** get attention -> ask where place is -> hear one/two-step direction -> confirm/thank.

**Listening Preview:** required before full publication.

---

### A1-TT-02 — Buy a ticket

**Goal:** ask for one straightforward ticket, answer one predictable detail, understand the price, and complete the purchase.

**Communication problem:** `request + information exchange + transaction`

**Likely shape:** request ticket -> destination/simple choice -> price -> complete purchase.

**Authoring note:** keep ticket options deliberately small; complex fare rules belong above A1.

**Listening Preview:** recommended.

---

### A1-TT-03 — Check into a hotel ★ Core

**Goal:** say you have a booking, provide or choose a safe booking identifier, answer one simple check-in question, and understand the next step.

**Communication problem:** `service check-in + give information`

**Likely shape:** state booking -> identify booking -> one simple confirmation -> receive room/basic instruction -> close.

**Privacy rule:** use fictional booking details or placeholders in authored content. Never hardcode real learner identity/contact data.

**Listening Preview:** required before full publication.

---

### A1-TT-04 — Check the right bus, train, or platform

**Goal:** ask whether a simple transport option is the correct one and confirm one number/platform/destination detail.

**Communication problem:** `ask information + confirm`

**Likely shape:** ask if this is correct -> hear number/platform/destination -> confirm -> thank.

**Listening Preview:** recommended.

## Work & Study — 3 missions

### A1-WS-01 — Say what you do or study

**Goal:** say whether you work/study and give one simple role/subject fact, then ask the other person back.

**Communication problem:** `give information + reciprocal question`

**Likely shape:** partner asks -> answer -> one simple detail -> ask back -> react.

**Privacy rule:** learner may use real, chosen, fictional, or placeholder information.

**Listening Preview:** optional/recommended.

---

### A1-WS-02 — Ask about a class or work schedule

**Goal:** ask where/when one familiar class, meeting, shift, or activity happens and confirm the answer.

**Communication problem:** `ask information + confirm`

**Likely shape:** ask time/place -> hear answer -> confirm -> thank.

**Listening Preview:** recommended.

---

### A1-WS-03 — Ask about a simple task

**Goal:** ask one concrete question needed to continue a familiar class/work task.

**Communication problem:** `ask for instruction/help`

**Possible task truths:** page number, room, item to use, one next action, or where to put/get something.

**Likely shape:** ask what/where -> receive short instruction -> confirm -> continue/thank.

**Authoring note:** the task must be visible and bounded. No explanation of complex responsibilities.

**Listening Preview:** optional/recommended.

## Home & Services — 3 missions

### A1-HS-01 — Ask for Wi-Fi or access details

**Goal:** ask for one access detail, understand/spell/confirm it if needed, and close.

**Communication problem:** `request information + repair/confirm`

**Likely shape:** ask for detail -> hear detail -> repeat/spell/confirm -> thank.

**Security note:** all passwords/codes in authored missions are fictional.

**Listening Preview:** recommended.

---

### A1-HS-02 — Book a simple appointment ★ Core

**Goal:** ask for a routine appointment, choose from a small set of offered days/times, confirm it, and close.

**Communication problem:** `request + simple arrangement`

**Likely shape:** ask for appointment -> hear two simple options -> choose -> confirm -> close.

**Authoring note:** no medical history, diagnosis, complex service details, or negotiation are required.

**Listening Preview:** required before full publication.

---

### A1-HS-03 — Report a simple problem and ask for help

**Goal:** state one concrete problem such as a light/Wi-Fi/object not working and ask for basic help.

**Communication problem:** `state problem + request help`

**Likely shape:** get attention -> state simple problem -> partner asks one basic clarification or confirms -> ask/accept help -> close.

**Authoring note:** keep the problem immediately observable and solvable. Explaining causes or negotiating compensation belongs above A1.

**Listening Preview:** recommended.

## Plans & Leisure — 3 missions

### A1-PL-01 — Ask about hobbies or free time

**Goal:** ask what someone likes doing, give one simple preference, and ask/answer one follow-up.

**Communication problem:** `social information exchange`

**Likely shape:** ask interest -> answer -> reciprocal question -> simple reaction.

**Listening Preview:** optional/recommended.

---

### A1-PL-02 — Invite someone and respond

**Goal:** make one simple invitation and handle a clear yes/no response naturally.

**Communication problem:** `invite + respond + close`

**Likely shape:** invite -> accept/decline -> short reaction -> close.

**Authoring note:** reasons for declining should stay extremely short at A1.

**Listening Preview:** recommended.

---

### A1-PL-03 — Make a simple plan ★ Core

**Goal:** agree one activity, day/time, and meeting place using a short collaborative exchange.

**Communication problem:** `arrange + confirm`

**Likely shape:** suggest activity -> choose/accept -> choose time -> confirm place -> close.

**Authoring note:** keep options small and partner collaborative. Negotiation over competing constraints starts later.

**Listening Preview:** required before full publication.

## A1 gaps deliberately left for higher levels

A1 does **not** need to force coverage of:

- explaining a complex reason
- narrating a past event in detail
- complaint negotiation
- trade-offs under competing constraints
- sustained disagreement
- subtle politeness/register choices
- mediation
- extended opinion support

Those should emerge naturally in A2–C2 as the communication problem changes.

# Map-to-mission production rule

For each mission promoted from this map into `missions/`:

1. Validate the real-world interaction flow.
2. Check language against the shared Englotti English level boundary.
3. Write compact scenario truth.
4. Author semantic conversation beats and learner intents.
5. Define correction focus and valid branches.
6. Use the dynamic contextual hint policy; do not write the primary runtime hint ladder as fixed answer cards.
7. Add Listening Preview when required/recommended by level policy.
8. Add adversarial QA cases.
9. Run real Gemini Live/audio QA before `published` status.
